# Watch Control

> [English](README.md) | **中文**

## 项目简介

Watch Control 让你在手表截图上选取坐标，保存到一个小型中转服务，然后从手表上的
悬浮窗调用这些坐标。

适用于手表屏幕太小、某些按钮不易点中的场景：你在桌面端看得清楚的地方选好位置，
手表上就会出现对应的按钮。

本项目是技术演示与参考实现，涵盖 Android 悬浮窗、ADB 调试接口、WebView 与原生
代码桥接、HMAC 请求签名，以及在 Android 应用中信任自签名证书。

## 需要什么

| 项目 | 说明 |
|---|---|
| Android 手表 | 已开启 ADB 调试与无线调试 |
| 一台电脑 | 运行桌面点选工具；需要 Python 3.9+ 与 `adb` |
| 一台中转机 | 可与电脑同一台；树莓派适合长期常开 |

需要 Python 3.9 或更高版本。不依赖任何第三方包，只用标准库。

## 快速开始

### 1. 生成配对密钥

```bash
./run.sh setup          # Linux / macOS
run.bat setup           # Windows
```

或手动执行：

```bash
mkdir -p ~/.config/watch-control
python3 -c "import secrets; print(secrets.token_hex(32))" \
  > ~/.config/watch-control/pairing.key
chmod 600 ~/.config/watch-control/pairing.key
```

### 2. 启动中转服务

```bash
./run.sh                # 监听 127.0.0.1:8787
```

启动时会打印配置信息。手表地址可以不填 —— 服务会从手表的首次请求中自动学习。

### 3. 手表开启 ADB

```bash
adb devices                  # 应为 device，而非 unauthorized
adb tcpip 5555               # 开启网络调试
adb connect <手表IP>:5555     # 验证
```

首次连接时手表会弹出授权提示，点**允许**。

### 4. 编译安装手表应用

```bash
cd android
python get_tools.py          # 下载 build-tools 与 android.jar
# 编辑 MainActivity.java，设置 BASE_URL、TOKEN、KEY
python compile.py
adb install -r watch-control.apk
```

如果中转服务跑在本机、且通过 USB 连接手表，可以把 `BASE_URL` 指向本机的局域网地址：

```java
private static final String BASE_URL = "https://192.168.1.100:8787";
```

使用自签名 HTTPS 证书时，把证书放到 `res/raw/pi_cert.pem`，
`network_security_config.xml` 已经引用了它。证书更换后需重新打包 APK。

### 5. 启动点选工具

```bash
./run.sh picker
```

浏览器打开 <http://127.0.0.1:8765>。左侧显示手表的实时画面，点击某个位置、
命名、按**记录这个点**；全部完成后按**保存点位**，坐标会写入本地并推送到中转服务。

### 6. 在手表上使用

打开手表上的应用，点击悬浮把手，会展开一圈按钮。点击按钮即把保存的坐标发给中转服务，
由它注入回手表。

## 配置项

所有配置均为环境变量。默认值一般够用，只有不同才需要设置。

| 变量 | 默认值 | 说明 |
|---|---|---|
| `WC_HOME` | `~/.config/watch-control` | 密钥与点位的存放目录 |
| `WATCH_ADDR` | 自动学习 | 手表的 `ip:port`，从请求中学习 |
| `PAIRING_KEY` | 读 `pairing.key` | 请求签名用的共享密钥 |
| `ADB_PATH` | `adb` | adb 可执行文件路径 |
| `WC_DEFAULT_DPI` | `120` | "恢复我的 DPI" 使用的值 |
| `HOST` / `PORT` | `127.0.0.1` / `8787` | 中转服务监听地址 |

| 变量 | 默认值 | 说明 |
|---|---|---|
| `BILIAUTO_SERVER` | `http://127.0.0.1:8787` | 点选工具连接的中转地址 |
| `BILIAUTO_KEY` | 读 `pairing.key` | 点选工具的签名密钥 |
| `BILIAUTO_APP` | 空 | 将点位限定于某个应用包名 |
| `ADB_SERIAL` | 自动 | 点选工具的目标设备序列号 |

## 工作原理

```
┌─────────────────┐   签名 HTTP 请求    ┌──────────────┐
│  桌面浏览器      │ ──────────────────> │  中转服务     │
│   点选页面       │    保存时推送       │  (树莓派/PC)  │
└─────────────────┘                     └──────┬───────┘
                                               │ adb
                                               │
                                        ┌──────▼───────┐
                                        │     手表      │
                                        │   （屏幕）    │
                                        └──────┬───────┘
                                               │ 悬浮窗
                                        ┌──────▼───────┐
                                        │  悬浮层上的   │
                                        │    按钮       │
                                        └──────────────┘
```

点选工具通过 adb 抓取手表画面、记录坐标，并推送到中转服务。手表应用绘制悬浮层，
按钮被按下时把坐标回报给中转服务，由它在手表的相同位置注入一次点击。

## 安全说明

请求在 `X-Bili-Sign` 头中携带 HMAC-SHA256 签名：

```
HMAC-SHA256(配对密钥, METHOD + "\n" + PATH + "\n" + BODY)  的十六进制
```

密钥是 `pairing.key` 中的 64 个 ASCII 字符，而非按十六进制解析后的 32 字节。
路径部分不包含查询字符串。

中转服务默认只监听 `127.0.0.1`。在没有反向代理与 TLS 的情况下将其暴露到公网并不妥当。

手表地址从入站请求中学习，因此能够跟随蜂窝网络的动态 IPv6 变更。若希望使用固定地址，
可设置 `WATCH_ADDR`，在尚无请求到达时它会生效。

## 已知限制

悬浮层无法覆盖系统界面，也无法覆盖主动禁用悬浮的应用。部分厂商 ROM 的限制比原生
Android 更严格；如果悬浮层不显示，请检查「显示在其他应用上层」是否已允许。

调整显示密度会改变屏幕逻辑尺寸，悬浮把手会被夹回可视范围，而非吸附到边缘。

在低于 90 的 WebView 版本中，非安全上下文不提供 `crypto.subtle`。手表应用通过
Java 桥接计算签名，因此仅在移除该桥接时才会受影响。

## 问题排查

**手表应用一直显示「连接中」。**
多半是 APK 中缺少证书。自签名证书会在 TLS 握手阶段失败，因此
`onReceivedSslError` 不会被触发。请确认 `res/raw/pi_cert.pem` 存在并重新编译。

**点击按钮没有反应。**
`WATCH_ADDR` 不正确，或手表未开启网络调试。在中转机上执行 `adb devices`，
手表应显示为 `device`。

**悬浮层里没有出现点位。**
在点选工具中按下**保存点位**，然后刷新悬浮层。点选工具的状态栏会显示是否已连上中转服务。

**请求返回 401。**
密钥不正确。请比对中转机上的 `pairing.key` 与点选工具使用的值。
